AI Content Gateway - Project Overview
=====================================

Purpose
-------
This is a Java 21 and Spring Boot REST API that accepts text and a target
language, asks Google's Gemini API to translate the text and assess its
safety, then returns the translation and moderation result to the caller.

Request flow
------------
1. The application receives POST /api/content/process.
2. ContentController validates the incoming request and passes it to
   ContentService.
3. ContentService builds a prompt and sends it to Gemini using Spring's
   RestClient.
4. The service reads the provider response, parses the model's JSON analysis,
   and checks that translatedText, safe, and reason have the expected types.
5. The API returns the original text, translated text, safety decision, and
   moderation message. Provider failures or invalid provider responses result
   in a 502 Bad Gateway response.

HTTP API
--------
Method: POST
Path:   /api/content/process
Content-Type: application/json

Example request:
{
  "text": "Hello, how are you?",
  "targetLanguage": "Turkish"
}

The text must not be blank and can be at most 10,000 characters. The target
language must not be blank and can be at most 100 characters.

The response contains:
- originalText: the submitted text
- translatedText: the translation returned by Gemini
- safe: the model's validated safety decision
- moderationMessage: a success message or the reason when the content is
  considered unsafe

Main source layout
------------------
src/main/java/com/yigitaslan/ai_content_gateway/
  AiContentGatewayApplication.java   Spring Boot application entry point
  config/RestClientConfig.java       Configures the Gemini HTTP client
  controller/ContentController.java  Defines the REST endpoint
  service/ContentService.java        Handles prompt, provider call, and parsing
  dto/ContentRequestModel.java       Validated API request
  dto/ContentResponseModel.java      API response
  dto/external/GeminiRequest.java    Gemini request data model
  dto/external/GeminiResponse.java   Gemini response data model

Configuration
-------------
Application settings are in src/main/resources/application.properties.
The server listens on port 8080 by default.

Set the Gemini API key in the GEMINI_API_KEY environment variable before
starting the application. The application intentionally fails to start when
the key is missing; do not put real API keys in source control.

Build, test, and run
--------------------
Run all tests:
  .\mvnw.cmd test

Package the application:
  .\mvnw.cmd package

Run the application on Windows after setting the key:
  $env:GEMINI_API_KEY = "your-api-key"
  .\mvnw.cmd spring-boot:run

Testing
-------
The test suite includes an application context test and service tests that
check safe and unsafe results as well as invalid provider responses. The
service tests use a mock HTTP server and do not call Gemini.

Important note
--------------
Safety analysis is generated by an AI model and is not a guaranteed content
moderation system. Do not treat the result as a substitute for independent
policy enforcement in safety-critical applications.
